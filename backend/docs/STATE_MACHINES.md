# State Machines

## Direct sale
SALE_CREATED → BUYER_PENDING → BUYER_ACCEPTED → PAYMENT_PROCESSING → PAYMENT_CONFIRMED → ESCROW_HELD → TRANSFER_PENDING → TRANSFER_IN_PROGRESS → OWNERSHIP_TRANSFERRED → HANDOVER_PENDING → HANDOVER_CONFIRMED → PAYOUT_PROTECTION → PAYOUT_PENDING → PAYOUT_PROCESSING → PAYOUT_CONFIRMED → COMPLETED.

Exceptional states include CANCELLED, EXPIRED, PAYMENT_FAILED, TRANSFER_BLOCKED, RELEASE_FAILED, DISPUTED and MANUAL_REVIEW.

## Auction
DRAFT → ACTIVE → ENDED → payment → escrow → transfer → handover → payout; unpaid winners follow configured failure handling.

## Authorization
PENDING → ACTIVE → REVOKED/EXPIRED/REJECTED.

## Support
OPEN → IN_PROGRESS → WAITING_USER → RESOLVED → CLOSED.

## Round 2 canonical Direct Sale machine

`SALE_CREATED → BUYER_PENDING → BUYER_ACCEPTED → PAYMENT_PROCESSING → PAYMENT_CONFIRMED → ESCROW_HELD → TRANSFER_PENDING → TRANSFER_IN_PROGRESS → OWNERSHIP_TRANSFERRED → HANDOVER_PENDING → HANDOVER_CONFIRMED → PAYOUT_PROTECTION → PAYOUT_PENDING → PAYOUT_PROCESSING → PAYOUT_CONFIRMED → COMPLETED`

Alternative terminal/review states include `CANCELLED`, `EXPIRED`, `FAILED`, `TRANSFER_BLOCKED`, `DISPUTED`, `MANUAL_REVIEW`, and `PAYOUT_REVIEW_REQUIRED`.

Every sensitive transition is server-side and guarded by PostgreSQL row locks where concurrency matters. Direct-sale expiration is two hours from server time.
